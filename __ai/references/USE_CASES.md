# Use cases and acceptance criteria

Observable behavior the client must exhibit. Grouped by area; each item is a test target.

## A. Template issuance

| # | Case | Acceptance |
| --- | --- | --- |
| A1 | Click a form button | Produces a pre-filled AcroForm PDF. No signer involved, no chain write |
| A2 | Pre-fill from context | Chain-derived context is written into `zarya.context.*` as read-only display fields |
| A3 | Operation recorded first | `operationRef` is persisted before the file reaches the user. A crash mid-issue leaves no unrecorded reference |
| A4 | Reproducible output | Same operation and schema version produce a byte-comparable form, so a fixture can pin it |
| A5 | Clean template | Generated file contains no scripts, actions, embedded files, or external references — it passes the app's own ingestion checks |
| A6 | Unavailable context | If a required chain read fails, issuance fails with a clear message rather than emitting a form with blank context |

## B. Form intake

| # | Case | Acceptance |
| --- | --- | --- |
| B1 | Import one filled form | Parses without sending a transaction; yields allow-listed intents or a clear validation error |
| B2 | Import many files or a folder | Creates a persisted batch; all files parsed and validated before any write |
| B3 | Invalid item in batch | Isolated; independent valid items still submittable; batch may end `PARTIAL` |
| B4 | Duplicate file | Detected by content hash; shown as already processed, not resubmitted |
| B5 | Semantic duplicate | Different files, same logical operation — detected by operation identity plus chain preflight. `hasVoted` is the final protection |
| B6 | Unknown schema version | Rejected with a clear message. Never parsed on a best-effort basis |
| B7 | Unknown or misspelled field name | Rejected. Never fuzzy-matched to the nearest known field |
| B8 | Tampered app-authored field | The file's `votingId`/`contract`/`organ` disagree with the record for its `operationRef`. Surfaced as a tamper warning; the database values are used and the file's are never read for value |
| B9 | Missing `operationRef` | Treated as unbound: full schema validation plus chain preflight, with no tamper check available |
| B10 | `operationRef` unknown or already completed | Rejected or shown as already processed. Never submitted blindly |
| B11 | Hostile PDF | Embedded JavaScript, launch or URI action, embedded file, external reference, compression bomb, or corrupted xref — rejected without executing or fetching anything |
| B12 | XFA present | Rejected. Never choose between XFA and AcroForm values |
| B13 | Flattened form | Detected and reported as flattened, not as an empty form |
| B14 | Encrypted form | Rejected with a clear message |
| B15 | Round trip | Issue a template, fill it programmatically, ingest it — the recovered intent matches the operation that produced it |

## C. Form-driven governance

Each maps one validated intent to one transaction, after preflight.

| # | Case | Call |
| --- | --- | --- |
| C1–C2 | Membership / revocation proposal | `createMembershipVoting`, `createMembershipRevocationVoting` |
| C3–C4 | Category / decimals proposal | `createCategoryVoting`, `createDecimalsVoting` |
| C5–C6 | Theme / statement proposal | `createThemeVoting`, `createStatementVoting` — `simpleMajority` eligibility |
| C7–C8 | Categorical / numerical value proposal | Preflight allowed category and cell organ; normalize fixed-point deterministically |
| C9–C10 | Cast `FOR` / `AGAINST` | `castVote(votingId, support, organ)` |
| C11 | Transfer chairmanship | Explicitly privileged; never routine or automatic |
| C12–C13 | Set organ quorum / approval | `setMinimumQuorum`, `setMinimumApprovalPercentage` |

Additional criteria:
- C2: preflight the Chairman-removal restriction (`CannotRemoveChairman`).
- C8: never silently round a governance value. Rounding or rejection policy is explicit and tested.
- C9–C10: authorization for ordinary members is organ membership. Chairman cross-organ behavior is unverified — preflight must not reject it. See `DOCUMENTATION_STATUS.md`.
- C12–C13: signer verified as Chairman where possible, never generated by the executor, and a later threshold change does not retroactively alter an existing voting. Percentage unit and base come from the contract; `51` is not reinterpreted.

## D. Bulk execution

| # | Case | Acceptance |
| --- | --- | --- |
| D1 | Bulk voting | Many `castVote` intents; one intent per transaction |
| D2 | Mixed batch | Proposals, votes, and privileged configuration together |
| D3 | Dependency | A later operation may need an earlier voting's ID. Symbolic references only if the form schema defines them |
| D4 | Failed dependency | Dependents blocked; unrelated items still processable |
| D5 | Long-lived dependency | May wait days. `WAITING_FOR_ONCHAIN_CONDITION` survives restarts |
| D6 | Partial submission | Confirmed items are never rolled back |
| D7 | Cancel | Stops only unsent work; mined transactions remain final |
| D8 | Resume | Restart or re-import reconciles and continues rather than replaying |

## E. Preflight and write failures

Each maps to a decoded custom error where the contract provides one.

| # | Case | Expected handling |
| --- | --- | --- |
| E1 | Not authorized for organ | `NotActiveMember`. Do not apply a member-only rule to a Chairman vote |
| E2 | Voting expired | `VotingNotActive` — do not cast; the executor may later finalize |
| E3 | Already voted | `AlreadyVoted` — idempotent completion, not a catastrophic error |
| E4 | Wrong network | Block all writes if chainId is not Sepolia |
| E5 | Wrong or missing contract | Block writes if the code or version check fails |
| E6 | Insufficient gas funds | Blocked or retryable; batch state stays coherent |
| E7 | RPC unavailable | Never convert unknown pending state into failed. Reconcile after recovery |
| E8 | State changed after preflight | Decode the revert and re-read chain state |
| E9 | Not Chairman | `NotChairman`. Since no `getChairman()` exists, this is discovered by simulation |
| E10 | Wrong organ encoding | `InvalidOrgan` / `UnknownRegion` — suspect the region-enum trap before anything else |

## F. Transaction recovery

| # | Crash window | Expected repair |
| --- | --- | --- |
| F1 | Before broadcast | Item remains retryable |
| F2 | After signing | Rebroadcast the identical raw transaction if an outbox exists; otherwise do not claim exactly-once |
| F3 | After broadcast or mining | Startup repairs local status from receipt and domain state |
| F4 | Pending | Never send a fresh higher nonce as a naive retry |
| F5 | Stuck | Surface `STUCK` and re-check. Replacement-by-fee is a separate feature using the same nonce |

## G. Receipts

| # | Case | Acceptance |
| --- | --- | --- |
| G1 | Transaction confirms | The returned form is stamped: `zarya.receipt.*` filled from the transaction record, then flattened |
| G2 | Transaction reverts | Still stamped, with `status = REVERTED` rendered as prominently as `CONFIRMED` |
| G3 | Broadcast but unconfirmed | No final receipt. Any provisional artifact says `PENDING` and is superseded on confirmation |
| G4 | Outcome unprovable | No receipt. Absence means "unknown", never "failed" |
| G5 | User pre-filled a receipt field | Overwritten unconditionally from the transaction record |
| G6 | Receipt re-imported | Rejected by the `txHash` marker; rejected again by the flattened-form check if the marker is stripped |
| G7 | `executeVoting` receipt | States the transaction outcome; does not claim the proposal passed |
| G8 | Receipt lost | Regenerated from the stored form plus transaction record, with no chain write |
| G9 | Batch of receipts | Written to one per-batch directory, named from `operationRef` and transaction hash — no dialog per form |
| G10 | Logo and identity | The Zarya logo appears on templates and receipts; no key material appears anywhere in the output |

## H. Automatic executive operations

| # | Case | Acceptance |
| --- | --- | --- |
| H1 | Discover overdue voting | Via `VotingCreated` cursor; `endTime <= chainTime && !finalized` |
| H2 | Execute | `executeVoting(votingId)` only. Never supplies policy |
| H3 | Accepted | Reconcile the applied mutation from `VotingFinalized` and domain reads — not from a `ValueAdded` event, which does not exist |
| H4 | Rejected or insufficient | `InsufficientVotes`. **Behavior unverified** — do not treat as transient, and do not report a political outcome as a technical failure. See `DOCUMENTATION_STATUS.md` |
| H5 | Nothing to execute | Healthy no-op; no transaction sent |
| H6 | Manual `Run now` | Runs the same full reconciliation loop |
| H7 | Worker restart | Reconciles rather than relying on lost timers |
| H8–H9 | Another client executed first, or a race | `VotingAlreadyFinalized` — re-read and classify as completed |
| H10 | Eligibility changed after creation | Execution uses the voting's snapshot, never today's organ configuration |

## I. UI and audit

| # | Case | Acceptance |
| --- | --- | --- |
| I1 | Form buttons | One button per supported operation, each issuing a pre-filled template |
| I2 | Batch overview | Ready, processing, confirmed, failed, blocked, skipped counts plus per-form status |
| I3 | Executive status | Health plus waiting/ready/pending/failed counts and one `Run now` |
| I4 | Transaction detail | Form identity and hash, `operationRef`, normalized intent, signer, contract, chain, tx hash, receipt, decoded error |
| I5 | Audit trace | `issued template → returned form → intent → transaction → chain result → receipt` |
| I6 | Tamper disclosure | A form whose app-authored fields diverge from its record shows the divergence plainly before submission |
| I7 | Receipt access | A confirmed item exposes its receipt, and can regenerate it if the file is gone |
| I8 | Configuration audit | Normalized organ and value plus tx hash. Effective thresholds cannot be shown — no getter exists |

## J. Read-only domain features

The app may read matrix themes, statements, categories, and history for validation, status, aggregation, and template pre-fill. These are read-only and must not be coupled to form parsing. Do not build UI that assumes a getter the ABI lacks — see the "Not exposed" table in `CONTRACT.md`.
